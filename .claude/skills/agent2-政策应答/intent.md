## Q1：这个 skill 做什么？

agent2「政策应答」面向城市更新与房地产投资领域的业务人员，处理自然语言业务政策类问题。它采用 **P2 最简化方案**（替代 V1 的 sandbox 查表）：直接由 LLM 读取 references/ 三份明文文档 + 被动消费 [RETRIEVED CONTEXT] 块（由上游注入的政策条款候选）执行规则匹配。

### 核心执行链（4 步，纯 LLM 推理）

1. **F1 政策检索**：消费 `[RETRIEVED CONTEXT]` 块（用户问题做 query 的语义检索结果）。若 [RETRIEVED CONTEXT] 为空 → fallback 到 `references/典型问答场景.md` 4 类场景关键词匹配
2. **H1 5 维门槛校验**（硬约束，逐条校验，全部通过才进入评分）：
   - 城市（必须 ∈ `references/15-试点城市.md` 的 15 城名单）
   - 项目类型（拆除重建 / 保留微更新 / 混合）
   - 资产规模（≥1亿 / 1000万-1亿 / <1000万）
   - 业主资质（国企 / 民企 / 混合所有制）
   - 业态方向（商业 / 办公 / 文旅 / 工业仓储 / 居住 / 公共服务）
3. **S1/S2 评分**（软约束，参考 `references/政策门槛表.md`）：
   - S1 适用强度（权重 0.5，资金额度/减免比例/容积率奖励幅度/期限，0-100）
   - S2 申请路径可行性（权重 0.5，申报通道明确度/历史成功案例/审批周期，0-100）
4. **排序 + 输出**：综合分 `= S1 × 0.5 + S2 × 0.5`，降序取 Top1-Top3，输出 4 字段 JSON 应答结论对象

### 与 V1 的差异

| 维度 | V1（设计） | V2（实施） |
|---|---|---|
| 数据源 | 向量库 + sandbox 脚本查表 | [RETRIEVED CONTEXT] 被动注入 + references/ 明文附表 |
| 查表机制 | Python 脚本 | LLM 直接读 markdown |
| 失败兜底 | sandbox_error → fallback-v1-llm | references/ 典型问答场景关键词匹配 |
| 文件数 | scripts + references | 仅 references（3 份） |

## Q2：何时触发？

### 应当触发（MUST trigger）

满足以下任一情形即应触发 agent2：

- 用户提出**专项债资格类**问题（含"自审自发"15 试点城市资格、申报通道、资金额度等）
- 用户提出**政策奖励类**问题（城市专项资金、税费减免、容积率奖励等）
- 用户提出**REITs 退出类**问题（基础设施 REITs 路径、商业 REITs、消费基础设施 REITs 等）
- 用户提出**税费减免类**问题（房产税、土地使用税、增值税即征即退、契税减免等）
- 用户提出**试点城市资格判定**问题（15 城名单归属）
- 用户提出**金融政策类**问题（专项债政策、政策性资金试点城市规则、各类政策性资金城市分档）
- 用户提出**多政策叠加**问题（如"专项资金 + 税费减免 + 容积率奖励能否同时享受"）

### 不触发场景（near-miss，应转交其他 agent）

- **agent1 闸门类问题**：项目准入闸门、硬约束清单判别（不属于政策咨询）
- **agent3 融资类问题**：融资工具组合、融资结构设计（不属于政策条款检索）
- **agent4 财务类问题**：财务测算、IRR/NPV 评估（不属于政策适用性）
- **agent5 失败案例类问题**：历史失败项目复盘、风险案例参考（不属于政策应答）
- **agent6 双层决策类问题**：投资拓展维度的最终红绿灯聚合判断（agent2 仅作为其政策维度输入源）
- **通用任务**：PDF 抽取、办公问答、文保法解读、纯法律咨询、学术研究、市场调研

### 触发判定原则

- 关键词命中（专项债 / 政策奖励 / REITs / 税费减免 / 试点城市 / 政策性资金等）仅是必要条件
- 还需语义上"询问政策适用性、申报路径、资格判定、支持力度"才触发
- 仅提到"政策"二字但实际问的是法律、市场、财务测算 → 不触发
- 边界模糊时，宁可保守漏触发，由用户手动指定 agent2

## Q3：关键判据有哪些？

### F1 政策检索（被动注入 + references 兜底）

- **首选数据源**：`[RETRIEVED CONTEXT]` 块（外部已注入的政策条款候选集合，每条含政策名称 + 条款原文 + 来源库标识）
- **回退数据源**（fallback）：当 [RETRIEVED CONTEXT] 为空 / 未注入时，读 `references/典型问答场景.md` 4 类场景（专项债资格 / 政策奖励 / REITs 退出 / 税费减免）的关键词 + H1 门槛要点做关键词匹配
- **强约束**：
  - F1 候选集为空（[RETRIEVED CONTEXT] 空 + references 关键词也未命中）→ MUST 输出"未检索到适用政策"，可适用政策清单字段为空数组 `[]`
  - **禁止幻觉编造政策条款**（不在 [RETRIEVED CONTEXT] 也不在 references 中的政策一律不得出现在可适用政策清单）
  - **MUST** 在建议动作中提示人工复核

### H1 适用门槛校验（硬约束，5 维全部通过才进入评分）

| # | 维度 | 校验要点 | references 查表位置 |
|---|---|---|---|
| 1 | 试点城市资格 | 项目所在地是否在 15 试点城市（北京/上海/广州/深圳/杭州/成都/武汉/西安/重庆/南京/天津/长沙/青岛/郑州/厦门） | `references/15-试点城市.md` |
| 2 | 项目类型 | 拆除重建 / 保留微更新 / 混合（部分政策仅支持保留微更新） | `references/政策门槛表.md` |
| 3 | 资产规模 | ≥1亿 / 1000万-1亿 / <1000万（不同政策的最低资产门槛） | `references/政策门槛表.md` |
| 4 | 业主资质 | 国企 / 民企 / 混合所有制（部分政策限定主体） | `references/政策门槛表.md` |
| 5 | 业态方向 | 商业 / 办公 / 文旅 / 工业仓储 / 居住 / 公共服务（部分政策支持目录限定） | `references/政策门槛表.md` |

- **任一不符** → 标记"门槛不符"，MUST 附具体缺口条件（如"项目所在地非 15 试点城市" / "业态方向数据中心不在专项债支持目录"），列入"未适用政策及原因"
- **全部通过** → 进入 S1/S2 评分

### S1 适用强度（软约束，权重 0.5【待校准】）

- 评分维度：资金额度 / 减免比例 / 容积率奖励幅度 / 期限
- 评分区间：0–100（闭区间）
- 评分参考：
  - 90-100：高额度 + 长期限 + 高减免比例（如专项债额度 > 项目投资 30% + 期限 ≥ 20 年）
  - 70-89：中等支持（如税费减免 30-50% + 期限 5-10 年）
  - 50-69：一般支持（如容积率奖励 ≤ 10%）
  - 0-49：象征性支持或条款模糊

### S2 申请路径可行性（软约束，权重 0.5【待校准】）

- 评分维度：申报通道明确度 / 历史成功案例 / 审批周期
- 评分区间：0–100（闭区间）
- 评分参考：
  - 90-100：申报通道明确 + 同城有公开成功案例 + 审批周期 ≤ 6 个月
  - 70-89：通道明确 + 异地有参考案例 + 审批周期 6-12 个月
  - 50-69：通道部分明确 + 案例稀缺 + 审批周期 12-18 个月
  - 0-49：通道不明 + 无公开案例 + 审批周期 > 18 个月或不可预计

### 综合分排序公式（显式，禁止心算偏差）

```
综合分 = S1 × 0.5 + S2 × 0.5
```

- 仅对通过 H1 门槛的候选条款计算综合分
- 按综合分降序排序，取 Top（默认 Top1-Top3，按综合分高低）
- 综合分 MUST 保留 1 位小数（如 78.5）

## Q4：输出格式是什么？

agent2 输出**应答结论对象**（不是任何灯色信号对象），4 字段 JSON schema：

```json
{
  "业务问题": "<string, 回显业务人员原始问题>",
  "可适用政策清单": [
    {
      "政策名称": "<string>",
      "支持力度": "<S1 评分 + 文字描述, 如 '85 - 专项债额度可达项目投资 30%, 期限 20 年'>",
      "申请路径": "<S2 评分 + 文字描述, 如 '80 - 上海已有 3 例公开成功案例, 审批周期约 6 个月'>",
      "限制条件": "<string, 如 '仅限保障性租赁住房方向'>",
      "依据条款": "<string, 如 '《上海市城市更新专项资金管理办法》第 12 条'>",
      "综合分": "<S1×0.5 + S2×0.5, 数值, 如 82.5>"
    }
  ],
  "未适用政策及原因": [
    {
      "政策名称": "<string>",
      "不适用原因": "<门槛不符的具体缺口 OR 检索未命中>"
    }
  ],
  "建议动作": "<string, 如 '建议优先对接上海市住建委专项债通道, 同步准备保障性租赁住房认定材料>'"
}
```

### 字段语义

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 业务问题 | string | 是 | 对原始用户问题的简洁复述 |
| 可适用政策清单 | array | 是 | 通过 H1 门槛的条款列表，按综合分降序；F1 无命中时为空数组 |
| └ 政策名称 | string | 是 | 政策库中的官方名称 |
| └ 支持力度 | string | 是 | S1 评分（数值）+ 文字描述 |
| └ 申请路径 | string | 是 | S2 评分（数值）+ 文字描述 |
| └ 限制条件 | string | 是 | 政策本身附带的限定 |
| └ 依据条款 | string | 是 | 政策文件中的具体条款引用 |
| └ 综合分 | number | 是 | `S1×0.5 + S2×0.5`，必须显式给出 |
| 未适用政策及原因 | array | 是 | F1 命中但 H1 不符，或 F1 检索未命中的政策列表 |
| └ 政策名称 | string | 是 | 政策库中的官方名称；F1 未命中时填"—"或"无匹配政策" |
| └ 不适用原因 | string | 是 | 具体缺口（如"项目所在地非 15 试点城市"）或"检索未命中" |
| 建议动作 | string | 是 | 给业务人员的下一步动作建议 |

### 三种状态的 schema 表现

| 业务状态 | 可适用政策清单 | 未适用政策及原因 | 建议动作 |
|---|---|---|---|
| F1 无命中 | 空数组 `[]` | 含"—"或"无匹配政策"条目 | 含"建议人工复核" |
| H1 门槛全不符 | 空数组 `[]` | 列出所有候选条款 + 具体缺口 | 建议补齐缺口或换路径 |
| 部分可适用 | Top 条款按综合分排序 | 列出未通过门槛的候选 + 缺口 | 建议优先推进 Top1 |

### 强约束

- **绝对禁止**输出任何灯色字段（不出现"灯色 / red / yellow / green / 红绿灯 / light / color"等字眼）
- **绝对禁止**跳过 H1 门槛直接给"可适用"结论
- **绝对禁止**在 F1 候选集为空时幻觉编造政策（既不在 [RETRIEVED CONTEXT] 也不在 references 中的政策一律不得输出）
- 综合分必须显式给出数值，不可仅以文字描述代替
- 综合分公式必须显式：`综合分 = S1 × 0.5 + S2 × 0.5`

## Step 1: F1 政策检索（V3 三层混合：被动注入 + 主动 sandbox 检索 + references 兜底）

> **6 条 pushy 硬规则（agent2 V3 版本）**：
> 1. **不得跳过** Step 0（references 三份文档 + sandbox bootstrap 都要走）
> 2. **不得估算**（H1 5 维门槛 + S1/S2 评分必须按 references/政策门槛表.md 表格查表，不得心算）
> 3. **不得 fallback 编造**（三层检索都未命中 → 输出"未检索到适用政策"，禁止幻觉政策）
> 4. **不得心算综合分**（必须显式给出 `S1 × 0.5 + S2 × 0.5` 公式与数值，保留 1 位小数）
> 5. **必须 schema**（输出必须符合 §6 schema，4 字段缺一不可）
> 6. **必须查表**（H1 5 维校验必须查 references/15-试点城市.md + references/政策门槛表.md）

### F1 主流程（三层混合检索）

```python
# 输入：用户业务问题 + [RETRIEVED CONTEXT] 块（外部注入）+ sandbox 可用性标志
candidates = []

# === 层 1（被动消费）：[RETRIEVED CONTEXT] 块 ===
if "[RETRIEVED CONTEXT]" in user_input:
    candidates = parse_retrieved_context(user_input["[RETRIEVED CONTEXT]"])
    # 每条候选含：政策名称 + 条款原文 + 来源库标识（KB01-REITs / KB03-专项债 等）

# === 层 2（主动检索）：sandbox 直连 kb_chunks_meta ===
# 触发条件：层 1 命中 < 3 条 OR 用户问题包含明确政策关键词（"REITs" / "专项债" / "958 号文" / "1014 号文" 等）
if SANDBOX_AVAILABLE and (len(candidates) < 3 or has_explicit_policy_keyword(user_input)):
    keyword = extract_search_keyword(user_input["业务问题"])
    # sandbox.runCode 调用
    extra_chunks = sandbox.runCode(f'''
        from libsql_client import query_kb_by_keyword
        results = query_kb_by_keyword("{keyword}", top_k=5)
        # 返回 list of dict: {chunk_id, kb_id, chunk_type, clause_label, content}
    ''', language='python')
    candidates.extend(extra_chunks)
    # 去重（按 chunk_id 去重）

# === 层 3（兜底）：references/典型问答场景.md 关键词匹配 ===
if not candidates:
    scene_match = match_scene_by_keywords(user_input["业务问题"])
    if scene_match:
        candidates = scene_match.fallback_candidates

# 三层都未命中 → 输出未命中
if not candidates:
    return {
        "业务问题": user_input["业务问题"],
        "可适用政策清单": [],
        "未适用政策及原因": [{"政策名称": "—", "不适用原因": "检索未命中 - 三层检索均未命中（[RETRIEVED CONTEXT] 空 + sandbox 不可用或 0 命中 + references 关键词未命中）"}],
        "建议动作": "建议人工复核政策专员或地方发改委窗口"
    }
```

### 关键词提取（V3 新增）

`extract_search_keyword` 优先级：
1. 用户问题中明确提到的政策编号（如 "958 号文" / "1014 号文" / "52 号文" / "国办发〔2024〕52 号"）→ 直接用作关键词
2. 政策类别关键词（专项债 / REITs / 城市更新 / 保障性租赁住房 / 自审自发 / 容积率奖励 / 税费减免）
3. 项目特征关键词（文旅 / 产业园区 / 商业提质 / 老旧厂房 / 仓储物流）
4. 兜底：用户问题的核心名词短语

`has_explicit_policy_keyword` 判断：用户问题包含上述 1-3 类关键词之一即 True。

### S1 适用强度（软约束，权重 0.5【待校准】）

- **评分维度**：资金额度 / 减免比例 / 容积率奖励幅度 / 期限
- **评分区间**：0–100（闭区间）
- **评分参考**（详见 `references/政策门槛表.md`）：
  - 90-100：高额度 + 长期限 + 高减免比例（如专项债额度 > 项目投资 30% + 期限 ≥ 20 年）
  - 70-89：中等支持（如税费减免 30-50% + 期限 5-10 年）
  - 50-69：一般支持（如容积率奖励 ≤ 10%）
  - 0-49：象征性支持或条款模糊
- **MUST** 在"支持力度"字段中给出 S1 数值 + 文字描述

### S2 申请路径可行性（软约束，权重 0.5【待校准】）

- **评分维度**：申报通道明确度 / 历史成功案例 / 审批周期
- **评分区间**：0–100（闭区间）
- **评分参考**（详见 `references/政策门槛表.md`）：
  - 90-100：申报通道明确 + 同城有公开成功案例 + 审批周期 ≤ 6 个月
  - 70-89：通道明确 + 异地有参考案例 + 审批周期 6-12 个月
  - 50-69：通道部分明确 + 案例稀缺 + 审批周期 12-18 个月
  - 0-49：通道不明 + 无公开案例 + 审批周期 > 18 个月或不可预计
- **MUST** 在"申请路径"字段中给出 S2 数值 + 文字描述

## 5. 判定层（按顺序逐条判定 F1 候选集中的每一条款）

### Step 1：F1 无命中（候选集为空）

- 输出："未检索到适用政策"
- 建议动作中 **MUST** 包含"人工复核"
- 可适用政策清单字段为 `[]`
- 未适用政策及原因中记录 `{ "政策名称": "—", "不适用原因": "检索未命中 - [RETRIEVED CONTEXT] 为空且 references 关键词未命中" }`

### Step 2：H1 门槛不符

- 列入"未适用政策及原因"
- **MUST** 在不适用原因中写明具体缺口（如"项目所在地河南非 15 试点城市"、"业态方向数据中心不在专项债支持目录"）
- **MUST NOT** 直接写"不符"或"不适用"等模糊措辞

### Step 3：可适用（5 项门槛全部通过）

- 计算综合分（公式显式）：

```
综合分 = S1 × 0.5 + S2 × 0.5
```

- **MUST** 严格按上述显式公式计算，避免算错（不得心算偏差）
- 按综合分降序排序，取 Top（默认 Top1-Top3，按综合分高低）
- 综合分 **MUST** 保留 1 位小数（如 78.5）

## 6. 结论层（应答结论对象 schema，V2 4 字段）

**MUST** 严格输出以下 4 字段 JSON 对象，**禁止**增删字段，**禁止**输出任何三色灯相关字段：

```json
{
  "业务问题": "<string, 回显业务人员原始问题>",
  "可适用政策清单": [
    {
      "政策名称": "<string>",
      "支持力度": "<S1 评分 + 文字描述, 如 '85 - 专项债额度可达项目投资 30%, 期限 20 年'>",

      "依据条款": "<string, 如 '《上海市城市更新专项资金管理办法》第 12 条'>",
      "综合分": "<S1×0.5 + S2×0.5, 数值, 如 82.5>"
    }
  ],
  "未适用政策及原因": [
    {
      "政策名称": "<string>",
      "不适用原因": "<门槛不符的具体缺口 OR 检索未命中>"
    }
  ],
  "建议动作": "<string>"
}
```

### 字段约束

- `业务问题` MUST = 用户原始问题（或简洁复述）
- `可适用政策清单` 为通过 H1 门槛的条款列表，按综合分降序；F1 无命中时为空数组 `[]`
- `可适用政策清单` 中每条 MUST 含 6 个子字段（政策名称 / 支持力度 / 申请路径 / 限制条件 / 依据条款 / 综合分），缺一不可
- `综合分` MUST = `S1 × 0.5 + S2 × 0.5`（保留 1 位小数）
- `未适用政策及原因` 为 F1 命中但 H1 不符，或 F1 检索未命中的政策列表
- `建议动作` MUST 给业务人员下一步明确动作建议（如"建议优先对接 X 部门 / 准备 Y 材料 / 转人工复核"）

## 7. 失败 / 降级路径

| 编号 | 场景 | 处理 |
|---|---|---|
| **F1** | [RETRIEVED CONTEXT] 块为空 + references 关键词未命中 | 输出"未检索到适用政策"，可适用政策清单 = `[]`，建议动作含"人工复核"，**禁止**幻觉编造政策 |
| **F2** | [RETRIEVED CONTEXT] 块未注入（外部检索失败） | 自动 fallback 到 `references/典型问答场景.md` 4 类场景关键词匹配；若关键词也未命中 → 走 F1 |
| **F3** | 用户问题中无法提取 5 维门槛信息（如未提项目所在地） | 列入"未适用政策及原因"，缺口 = "信息缺失（项目所在地未提供）"，建议动作含"补齐信息后重新咨询" |
| **F4** | 项目所在地不在 15 试点城市 | 该政策（如专项债自审自发）列入"未适用政策及原因"，缺口 = "项目所在地非 15 试点城市"，可建议改走一般专项债渠道 |
| **F5** | 业态方向不在政策支持目录（如数据中心 / 元宇宙） | 列入"未适用政策及原因"，缺口 = "业态方向 X 不在专项债/政策支持目录" |
| **F6** | 综合分计算偏差（>1 分误差） | 重算，综合分公式必须显式 `S1 × 0.5 + S2 × 0.5` |
| **F7** | 用户问"全部政策 / 所有政策"（无明确维度） | 提示用户细化维度（专项债 / REITs / 税费减免 / 容积率奖励），按细化后的维度逐条匹配 |
| **F8** | sandbox 不可用 / libSQL 连接失败 / query_kb_by_keyword 抛错（V3 新增） | 降级到 V2 P2 模式：仅用 [RETRIEVED CONTEXT] + references 关键词匹配，**MUST** 在应答结论对象的"建议动作"中标注"sandbox/libSQL 暂不可用，主动检索未执行"，不阻断应答输出 |

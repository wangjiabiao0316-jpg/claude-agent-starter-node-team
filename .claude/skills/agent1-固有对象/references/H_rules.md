## 1. H1 产权清晰度（硬约束）

> 输入：不动产文书 + 不动产登记合规接口（由 [RETRIEVED CONTEXT] 被动注入）+ 用户填写的 `不动产证号`。

### 1.1 H1.red 触发条件（任一命中 → H1 = red，输出 H1.red.X 编号）

| 编号 | 触发条件 | 数据来源 | 风险描述模板 |
|---|---|---|---|
| **H1.red.A** | 不动产证号无效 / 不一致 / 缺失 | 用户填写 + 不动产登记合规接口 | "不动产证号 {证号} 无效或与不动产登记库不一致，产权真实性无法确认" |
| **H1.red.B** | 产权人未到场或未授权（无法定代理人 / 无公证委托书） | 用户填写 + 不动产登记合规接口 | "产权人 {产权人姓名} 未到场且无法定授权，处置行为效力存疑" |
| **H1.red.C** | 共有产权人未全部同意（任一共有人书面反对或缺席） | 用户填写 + 共有人书面同意书 | "共有产权人 {未同意人姓名} 未出具书面同意，处分权受限" |
| **H1.red.D** | 涉及法院查封 / 诉讼中 / 行政限制处分 | 不动产登记合规接口（[RETRIEVED CONTEXT]） | "不动产被 {查封法院} 查封 / 涉及诉讼案号 {案号}，处分权受限" |

**H1.red 命中后处置**（短路逻辑）：

1. 输出 `灯色 = red`
2. `命中判据` 数组追加 `"H1.red.A"`（或对应编号）
3. `建议动作 = "终止"`
4. **直接退出 Step 3**，不再算 H2 / S 总分（V1 §1 L60 短路）

### 1.2 H1.yellow 触发条件（无 red 命中时检查）

| 编号 | 触发条件 | 数据来源 | 风险描述模板 |
|---|---|---|---|
| **H1.yellow.A** | 产权证号待补（用户承诺提供但当前未提供） | 用户填写 | "产权证号待补，需在条件推进阶段补齐不动产权属证明" |
| **H1.yellow.B** | 部分共有人书面同意（未全部，但多数已同意且无明确反对） | 用户填写 + 共有人书面同意书 | "共有产权人 {已同意人数} / {总人数} 已同意，需补齐全部共有人书面同意" |
| **H1.yellow.C** | 产权年限剩余 < 30 年（商业用地 40 年 / 综合 50 年 / 居住 70 年） | 不动产证号 + 用户填写 | "产权年限剩余 {剩余年限} 年，融资工具可期限受限（多数银行要求 ≥ 30 年）" |

**H1.yellow 命中后处置**：

1. 输出 `H1 子灯 = yellow`
2. `命中判据` 数组追加 `"H1.yellow.A"`（或对应编号）
3. 进入 Step 2 校验 H2，最终灯色至少 yellow

### 1.3 H1.green 触发条件

**所有以下条件全部满足时 H1 = green**：

- 不动产证号有效且与登记库一致（H1.red.A 不触发）
- 产权人到场或有效授权（H1.red.B 不触发）
- 共有产权人全部同意（H1.red.C 与 H1.yellow.B 均不触发）
- 不涉及法院查封 / 诉讼 / 行政限制（H1.red.D 不触发）
- 产权年限剩余 ≥ 30 年（H1.yellow.C 不触发）
- 产权证号已提供（H1.yellow.A 不触发）

**H1.green 命中后处置**：

1. 输出 `H1 子灯 = green`
2. `命中判据` 数组追加 `"H1.green"`
3. 进入 Step 2 校验 H2

## 3. H 顶层判定（短路逻辑）

按 V1 §1 L60-66 逐字保留：

```
if H1 == "red" or H2 == "red":
    灯色 = "red"
    建议动作 = "终止"
    # 短路退出，不再执行 S 软规则评分
elif H1 == "yellow" or H2 == "yellow":
    基础灯 = "yellow"  # S 总分仅可保持 yellow 或升级 green
    进入 Step 4 算 S 总分（仅在 S 总分 ≥ 75 且无 H yellow 时才可升级 green；H 任一 yellow 强制最终 yellow）
else:  # H1 + H2 全 green
    进入 Step 4 算 S 总分
```

**注**：H 任一 yellow 时，S 总分仅可作为「条件推进」参考，**不可升级 green**（V1 §1 L65：「H 命中黄 → 基础灯黄，叠加软约束（条件推进）」）。这是 V2 对 V1 §1 的严格化（避免 H yellow + S 高分误判 green）。

---

## 4. 与 references/S_rules.md 的衔接

- H 顶层判定输出 red 时，**短路退出**，不调 S_rules.md
- H 顶层判定输出 yellow 基础灯时，**仍调 S_rules.md 算 S 总分**，但最终灯色强制 yellow（S 总分仅作风险描述参考）
- H 顶层判定进入 green 分支时，**调 S_rules.md 算 S 总分**，按 75/60 阈值映射最终灯色

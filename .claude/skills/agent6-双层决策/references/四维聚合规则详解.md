# agent6 双层决策 — 四维聚合规则详解 (V2)

> 本文件为 agent6 SKILL.md V2 的 references 子文件。
> 完整复刻 agent6 工作流 md §1.2 的四维聚合规则 + V2 新增 `agent4._calc.engine` 强制规则。
> V1 留底：`四维聚合规则详解-V1.md`。

agent6 是聚合型智能体，对咨投建运四维子灯执行「先算子灯 → 再算顶层」的两层判定。
每个维度的输入字段、聚合公式、灯映射必须与下游 agent{N}_输出_schema.md 字段名严格一致。

V2 升级：所有规则已机器可读化，落地在 `references/decision_rules.json`，由 `scripts/decision_aggregator.py` 执行（不再依赖 LLM 心算）。


### 输入字段（来自下游 agent）

| 字段 | 来源 | 引用 schema |
|---|---|---|
| `agent1.灯色` | agent1 | `agent1_输出_schema.md` §1 `灯色` |
| `agent1.命中判据[]` | agent1 | `agent1_输出_schema.md` §1 `命中判据` |
| `agent5.校验灯` | agent5 | `agent5_输出_schema.md` §1 `校验灯` |
| `agent5.Top3案例[].失败模式` | agent5 | `agent5_输出_schema.md` §1 `Top3案例[].失败模式` |
| `agent5.根因重现判断` | agent5 | `agent5_输出_schema.md` §1 `根因重现判断` |

### 维度灯映射表（V2 sandbox 自动执行）

| 条件 | 设计咨询维度灯 | decision_aggregator.py 实现 |
|---|---|---|
| `agent1.灯色 = red` | **red** | 直接 if 分支 |
| `agent1.灯色 = yellow` 且 `agent5.Top3案例[].失败模式 ∈ {招商失败, 改造超预算, 业态误判}` | **red**（风险升级） | `_has_renovation_root_cause(agent5)` |

| `agent1.灯色 = green` 且 `agent5.校验灯 = green` | **green** | 直接 if 分支 |
| 其他 | **yellow**（保守降级） | 兜底 return |

### 维度灯映射表（V2 — engine 强制规则优先）

#### Step 1: engine 强制规则（覆盖常规规则）

| `agent4._calc.engine` | 处置 | 维度灯 |
|---|---|---|
| `numpy-financial` | normal（按常规规则） | 见 Step 2 |
| `python-bisection` | force_yellow | **yellow** |
| `timeout-at-30s` | force_yellow | **yellow** |
| `unavailable` | **force_red** | **red**（顶层硬规则触发） |
| `sandbox_error` | **force_red** | **red** |
| `not-invoked` | follow_v1（按 V1 规则） | 见 Step 2 |

#### Step 2: 常规规则（engine=normal 或 follow_v1 时执行）

| 条件 | 投资拓展维度灯 |
|---|---|
| `agent3.灯色 = red` 或 `agent4.业态门槛对照.达标结论 = 不达标` | **red** |
| `agent3.灯色 = yellow` 或 `agent4.业态门槛对照.达标结论 = 达标（非优）` | **yellow** |
| `agent3.灯色 = green` 且 `agent4.业态门槛对照.达标结论 = 优` | **green** |

> 注：投资拓展维度 red 触发顶层硬规则（详见 `顶层硬规则与决策权重.md`）。

## 维度四：业主平台维度子灯（权重 0.2【待校准】）

### 聚合规则公式

```
业主平台维度灯 = f(前三维度灯色, 数据完整度, 四维一致性, 上会材料可生成性)
```

### 输入字段

| 字段 | 来源 | 引用 schema |
|---|---|---|
| 前三维度灯色（设计咨询 / 投资拓展 / 建造实施） | agent6 内部 | 本文件 §维度一/二/三 |
| `agent1` / `agent3` / `agent4` / `agent5` 输出对象必填字段缺失数 | 4 个下游 agent | 各 agent_输出_schema.md |
| `agent3.可适用融资工具清单[].期限` | agent3 | `agent3_输出_schema.md` §1 |
| `agent4.现金流时序[]` | agent4 | `agent4_输出_schema.md` §1 |
| 上会材料可生成性 | agent6 内部 | `报告模板库.md` |

### 维度灯映射表（V2 sandbox 简化版）

| 条件 | 业主平台维度灯 | decision_aggregator.py 实现 |
|---|---|---|
| 前三维度任一 red | **red**（一致性硬规则） | `any(l == "red" for l in 三维.values())` |
| 前三维度全 green | **green** | `all(l == "green" for l in 三维.values())` |
| 其余（含数据缺失、四维矛盾） | **yellow** | 兜底 return |

> **V2 简化说明**：当前 V2 版本仅依据前三维度灯色判业主平台灯色；数据完整度 / 四维一致性 / 上会材料可生成性的细化逻辑留待 V3（参考 V1 §1.2 维度四）。

## 4 个维度的执行顺序（V2 sandbox 实现）

`decision_aggregator.py` 的 `decide()` 函数执行顺序：

1. 加载 `decision_rules.json`
2. 算维度一（设计咨询）：`_dim_light_设计咨询(agent1, agent5)`
3. 算维度二（投资拓展）：`_dim_light_投资拓展(agent3, agent4, rules)`（含 engine 强制）
4. 算维度三（建造实施）：`_dim_light_建造实施(agent1, agent5)`
5. 算维度四（业主平台）：`_dim_light_业主平台(三维)`
6. H 硬规则判定 → 否则 S 软规则聚合
7. 一致性校验（顶层与四维自洽）
8. 输出 schema（含 `_calc.engine = "decision-aggregator-v2"`）

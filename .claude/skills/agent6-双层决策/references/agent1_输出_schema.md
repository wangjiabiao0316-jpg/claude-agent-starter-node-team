# agent1 固有对象识别 — 结论层输出 schema (V2)

> 本文件为 agent6 SKILL.md V2 的 references 子文件。
> 引用源：`2026-08-03-agent1-固有对象识别-skill工作流.md` §1.5。
> V1 留底：`agent1_输出_schema-V1.md`。
> V2 变更：无字段层面变更；仅澄清 agent6 设计咨询维度 + 建造实施维度的引用关系。

agent6 设计咨询维度子灯聚合规则主信号源取自本 schema 的 `灯色` 字段；
H1 / H2 命中判据用于 agent6 建造实施维度（H2 文保条款）与顶层硬规则论证。

---

## 1. JSON Schema (V2)

```json
{
  "灯色": "red | yellow | green",
  "命中判据": ["H1.red", "H2.yellow", "..."],
  "风险点": ["查封未决", "文保核心保护区", "..."],
  "依据": {
    "H1": "不动产文书 + 不动产登记合规接口返回 X",
    "H2": "规划文件 Y / 文保等级 Z",
    "S_aggregate": "S1=82, S2=70 → 76"
  },
  "建议动作": "终止 | 条件推进 | 可推进"
}
```

---

## 2. 字段说明

| 字段 | 类型 | 取值 | agent6 引用方式 |
|---|---|---|---|
| `灯色` | enum | `red` / `yellow` / `green` | 设计咨询维度主信号；`agent1.灯色=red` 直接 → 设计咨询维度 red |
| `命中判据` | string[] | 如 `H1.red` / `H2.yellow` / `S_aggregate.NN` | `H1.red` 用于论证顶层硬规则；`H2.*` 用于建造实施维度（核心保护区 / 建控地带） |
| `风险点` | string[] | 自然语言短语 | 直接 copy 到 agent6 输出对象 `四维子灯.{设计咨询,建造实施}.依据` 字段 |
| `依据` | object | H1 / H2 / S_aggregate 三键 | 用于 agent6 输出对象 `四维子灯.{维度}.依据.agent1_*` 字段填充 |
| `建议动作` | enum | `终止` / `条件推进` / `可推进` | agent6 顶层 `建议动作` 的来源之一（red → 终止；yellow → 条件推进；green → 可推进） |

---

## 3. 红黄绿触发条件摘要

### 3.1 H1 产权清晰度（硬约束）

| 灯色 | 触发条件 |
|---|---|
| red | 存在查封 / 权属争议未决 / 共有权且共有人未同意 |
| yellow | 存在抵押但有明确解押路径 / 共有权但共意可协商 |
| green | 权属清晰无负担 |

> agent6 设计咨询维度聚合：`agent1.命中判据` 含 `H1.red` → 设计咨询维度直接 red。

### 3.2 H2 文保与规划硬约束（硬约束）

| 灯色 | 触发条件 |
|---|---|
| red | 文保核心保护区且改造不可经营 / 规划明确禁止该业态 |
| yellow | 文保建控地带需专项审批 / 规划有条件允许 |
| green | 无文保约束或约束可控 |

> agent6 建造实施维度聚合（V2 sandbox 自动识别）：
> - `agent1.命中判据` 含 `H2.red.文保核心保护区` → 建造实施维度 red
> - `agent1.命中判据` 含 `H2.yellow.建控地带` → 建造实施维度 yellow（Phase1 简化）
> - decision_aggregator.py 通过字符串匹配 `"H2" + "核心保护区"` / `"H2" + "建控地带"` 自动识别

---

## 4. 软约束聚合（仅 H 全绿时触发）

S1 更新意愿（权重 0.5【待校准】）+ S2 可经营性（权重 0.5【待校准】）

- S_aggregate ≥ 75 → green
- S_aggregate 60–75 → yellow
- S_aggregate < 60 → red

阈值【待校准】，本 references 仅落地 schema，不调参。

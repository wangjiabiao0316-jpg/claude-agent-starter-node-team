# agent6 双层决策 — 报告模板库（四类用户差异化视图）(V2)

> 本文件为 agent6 SKILL.md V2 的 references 子文件。
> 对应 agent6 工作流 md §1.6 输出对象 schema 中 `触发报告模板` 字段 + V2 自动映射规则。
> V1 留底：`报告模板库-V1.md`。

agent6 输出对象 `触发报告模板` 取值四选一：`投资人版 | 政府版 | 业主版 | 内部决策版`。
本文件定义每类视图的差异化说明、关键字段、生成触发条件、参考下游 agent 数据来源。

V2 升级：报告模板触发已**机器可读化**，落地在 `decision_rules.json` 的 `report_template_mapping` 字段，按顶层灯自动映射。

---

## 0. V2 自动映射规则（顶层灯 → 触发模板）

| 顶层灯 | 触发模板 | 说明 |
|---|---|---|
| `red` | **内部决策版（终止原因）** | 完整论证链备查；不外发其他视图 |
| `yellow` | **投资人版 + 政府版（条件推进）** | 投资人关注条件达成路径；政府关注合规条件 |
| `green` | **全部 4 类用户版** | 完整外发：投资人 / 政府 / 业主 / 内部决策 |

> 注：V2 简化触发规则。V1 中「按用户身份选择视图」的逻辑由 super-skill 编排器在前端按钮交互层处理（参考 super-skill 架构设计 §3.2 suggest_actions payload），agent6 仅按顶层灯输出 `触发报告模板` 字段。

## 5. 视图选择优先级（V2 简化版）

V2 由 `decision_rules.json.report_template_mapping` 按顶层灯自动选择：

```python
# decision_aggregator.py 实现
report_map = rules["report_template_mapping"]
触发报告模板 = report_map[顶层灯]  # red → 内部决策版；yellow → 投资人版+政府版；green → 全部 4 类
```

V1 中「按用户身份选择视图」的逻辑由 super-skill 编排器在前端 suggest_actions 按钮组处理（参考 `super-skill/plan/2026-08-08-super-skill-架构设计.md` §3.2），agent6 不再判断用户身份。

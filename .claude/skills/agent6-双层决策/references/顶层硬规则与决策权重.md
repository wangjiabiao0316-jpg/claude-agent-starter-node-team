> V1 留底：`顶层硬规则与决策权重-V1.md`。

agent6 在算完四维子灯后，按「先 H 硬规则，后 S 软规则」的顺序算顶层灯。
H 硬规则命中即终止聚合，软规则仅在无红时启动。

V2 升级：所有规则已机器可读化，落地在 `references/decision_rules.json` 的 `H_rules` / `S_rules` / `agent4_engine_mapping` 字段。

## 1. H 顶层硬规则（V1 §6 L322 逐字保留）

> **H 硬规则**：**设计咨询维度 = red 或 投资拓展维度 = red → 触发顶层 red（不推进）**

### 触发条件

四维中「设计咨询」或「投资拓展」任一维度子灯 = `red`。

### 触发路径（V2 增强：含 engine 强制规则）

#### 1.1 设计咨询维度 red 路径

- `agent1.灯色 = red`（H1 产权查封/权属争议/共有人未同意；H2 文保核心保护区且改造不可经营/规划明确禁止业态）
- `agent1.灯色 = yellow` 且 `agent5.Top3案例[].失败模式 ∈ {招商失败, 改造超预算, 业态误判}`（风险升级）

#### 1.2 投资拓展维度 red 路径

**优先级 1（V2 新增 — engine 强制）**：

- `agent4._calc.engine = unavailable` → 投资拓展 red
- `agent4._calc.engine = sandbox_error` → 投资拓展 red

**优先级 2（V1 常规）**：

- `agent3.灯色 = red`（可适用融资工具数 = 0）
- `agent4.业态门槛对照.达标结论 = 不达标`（IRR < 业态门槛下限）

### 触发后果

- 顶层灯 = **red**
- 顶层判据 = `H.关键维度硬规则（设计咨询=red 或 投资拓展=red）`
- 建议动作 = **终止 / 不推进**
- **不再继续软规则聚合**（决策权重 0.3/0.3/0.2/0.2 不参与计算）
- 输出对象 `条件推进事项[]` 列终止原因（如「投资拓展 维度 red」）
- 触发报告模板：`内部决策版（终止原因）`

## 3. 顶层判定层（V1 §6 L325-328，V2 sandbox 实现）

### Step 1：先算四维子灯

按 `四维聚合规则详解.md` §维度一/二/三/四 各维度聚合规则分别计算。
对应 `decision_aggregator.py` 的 `_dim_light_设计咨询` / `_dim_light_投资拓展` / `_dim_light_建造实施` / `_dim_light_业主平台`。

### Step 2：H 顶层硬规则判定

- 设计咨询维度 = `red` 或 投资拓展维度 = `red` → **顶层 red**（不推进）
- 顶层判据 = `H.关键维度硬规则（设计咨询=red 或 投资拓展=red）`
- 不再继续 Step 3

### Step 3：顶层软规则（仅当 Step 2 未触发时执行）

- **四维全 green 且一致** → **顶层 green**
  - 顶层判据 = `S.决策权重聚合（0.3/0.3/0.2/0.2）`
  - 建议动作 = `可推进`
- **存在 yellow（无 red）** → **顶层 yellow**（条件推进，列出黄级事项清单）
  - 顶层判据 = `S.决策权重聚合（0.3/0.3/0.2/0.2）`
  - 建议动作 = `条件推进`
  - 输出对象 `条件推进事项[]` 必填，逐维度列出 yellow 维度的可解决事项

## 4. 软规则聚合示例

### 示例 1：四维全 green → 顶层 green

| 维度 | 灯色 | 权重 |
|---|---|---|
| 设计咨询 | green | 0.3 |
| 投资拓展 | green | 0.3 |
| 建造实施 | green | 0.2 |
| 业主平台 | green | 0.2 |

→ **顶层 green**（顶层判据 = S.决策权重聚合；建议动作 = 可推进）

### 示例 2：存在 yellow（无 red）→ 顶层 yellow

| 维度 | 灯色 | 权重 |
|---|---|---|
| 设计咨询 | yellow | 0.3 |
| 投资拓展 | green | 0.3 |
| 建造实施 | yellow | 0.2 |
| 业主平台 | yellow | 0.2 |

→ **顶层 yellow**（顶层判据 = S.决策权重聚合；建议动作 = 条件推进；`条件推进事项[]` = ["设计咨询 维度 yellow", "建造实施 维度 yellow", "业主平台 维度 yellow"]）

### 示例 3：H 硬规则命中 → 顶层 red（不调权重）

| 维度 | 灯色 | 权重 |
|---|---|---|
| 设计咨询 | **red**（agent1.H1 查封） | 0.3 |
| 投资拓展 | green | 0.3 |
| 建造实施 | green | 0.2 |
| 业主平台 | red（一致性硬规则：三维任一 red） | 0.2 |

→ **顶层 red**（顶层判据 = `H.关键维度硬规则（设计咨询=red）`；建议动作 = 终止；**权重不参与计算**）

### 示例 4（V2 新增）：agent4 engine 强制 red → 顶层 red

| 维度 | 灯色 | 权重 | 备注 |
|---|---|---|---|
| 设计咨询 | green | 0.3 | |
| 投资拓展 | **red** | 0.3 | **agent4._calc.engine = unavailable → 强制 red** |
| 建造实施 | green | 0.2 | |
| 业主平台 | red（一致性硬规则） | 0.2 | |

→ **顶层 red**（顶层判据 = `H.关键维度硬规则（投资拓展=red）`；建议动作 = 终止；条件推进事项 = ["投资拓展 维度 red", "业主平台 维度 red"]）

## 5. 关键约束（V2 sandbox 强制校验）

- H 硬规则文本**逐字保留** V1 §6 L322 措辞，禁止改写
- 决策权重 0.3 / 0.3 / 0.2 / 0.2 必须**显式标注【待校准】**
- 软规则聚合**仅**在 H 硬规则未触发时启动
- 顶层灯与四维子灯必须论证一致（如顶层 green 时四维不可有 red；顶层 red 时至少有一维 red 且属 H 硬规则范围）
- **V2 新增**：`agent4._calc.engine ∈ {unavailable, sandbox_error}` 必须强制投资拓展维度 red，进而触发 H 硬规则
- **V2 新增**：`agent4._calc.engine ∈ {python-bisection, timeout-at-30s}` 必须强制投资拓展维度 yellow（不触发 H 硬规则，但会影响顶层 yellow）
